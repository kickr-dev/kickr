# kickr

The **kickr** CLI generates and maintains a repository layout from `.kickr.yml` and what its parsers detect, on top of the `gitlab.com/kickr-dev/engine` SDK.
Read [CONTRIBUTING.md](CONTRIBUTING.md) before writing a commit, since `refactor` releases a minor version here.

- Run `just test` and `just lint` when the change can affect them.
- Read the lint output, since the recipe exits 0 when [**golangci-lint**](https://golangci-lint.run) fails.
- Leave `just testdata` (the golden fixtures) and builds to the user, and name them when the change needs them.
- A change to the generation flow or its options (`engine.Options`) starts in the engine module, built against locally through the commented `replace` line of `go.mod`.

## Templates

The files under `pkg/generate/templates/_templates/` are the **source** of every generated file, even though most carry `Code generated by kickr; DO NOT EDIT.`, so edit them there.
The **kickr** CLI also generates this repository's own layout (`Justfile`, `scripts/just/` except `custom.just`, `.golangci.yml`, `.gitlab-ci.yml`, `.releaserc.yml`).
That layout is **output**, so change its template instead.

- A template set is `pkg/generate/templates/<topic>.go`, with its files under `_templates/`.
- Register it in `Generators` of `pkg/generate/generate.go`, and in the standalone command owning that part, if any.
- Put language logic in a template or a dedicated parser, and keep `Repository` and `Module` language-neutral (*e.g.* no `HasHugo()`).
- Remove an output that no longer applies with `GeneratePolicy: engine.RemoveIf(<predicate>, engine.PolicyDefault)`.
- A file the user also edits (*e.g.* `README.md`) uses `engine.GlobsWithPart` and `Sections` with `BEGIN_KICKR_<NAME>` and `END_KICKR_<NAME>` markers.
- Filter a module list once into a local var, and reuse it for both the guard and the loop.
- Keep each CI concern in its own pipeline template (`semantic-release.yml.tmpl`, `integration.yml.tmpl`, `deployment.yml.tmpl`), its overrides included.
- Configure or disable a to-be-continuous component job through its `inputs:`.
- Omit a disabled hand-written job entirely, which overrides the [**GitLab CI**](https://docs.gitlab.com/ci/) rule file's `when: never` here.

Done when the golden fixtures the change affects are named for the user to regenerate.

## Configuration schema

The `.schemas/kickr.v1.schema.yml` file is the source of truth.
The `.schemas/kickr.v1.schema.json`, `pkg/kickr/v1/kickr.go` and `pkg/kickr/v1/constants.go` files derive from it, despite the Go files' `Code generated by AI` marker.

1. Edit the yml.
2. Regenerate the JSON with `cd ./.schemas && go generate ./...`.
3. Update `kickr.go` (structs, GoDoc) and `constants.go` (enums) with the `schema-to-go` skill.

Done when the JSON, `kickr.go` and `constants.go` match the yml.

- Prefer an entry in an existing `options` or `exclude` enum (`group:item`, *e.g.* `vendor:workload`) over a new scalar key.
- Ask before picking a side when a config combination is ambiguous or contradictory (*e.g.* website hosting vs **Docker**), even when a previous answer seemed to settle it.

## Parsers, predicates and commands

- A predicate reading only the configuration goes in `pkg/kickr/v1/methods.go`.
- A predicate reading parsed state (languages, globs, executables) goes on `Repository` or `Module` in `pkg/generate/types`, next to helpers such as `Module.HasDocker()` and `Repository.ModulesWith()`.
- A parser is `pkg/generate/parser_<name>.go`, registered in `Parsers` of `pkg/generate/generate.go`, where order matters.
- A generator is `pkg/generate/generator_<name>.go`, registered in `Generators`.
- Declare a lookup list as a local of the function that needs it.
- A standalone command (*e.g.* `kickr chart`) is `internal/cobra/<name>.go` with `GroupID: groupStandalone`, wired in `Execute` of `internal/cobra/root.go`, with its `internal/cobra/<name>_test.go`.
- A standalone command includes only the templates its part owns, since a `RemoveIf` guard on a nil config deletes another platform's files.
- For the parts it includes, a standalone command behaves like the full generation.

## Tests

- Generation tests in `pkg/generate/generate_test.go` diff the output against the **golden** fixtures in `testdata/<TestName>/` through `test(ctx, t, repo, parsers...)`.
- Build a case config with `merge(t, base, tc.Config)`.
- Each test func declares its own `golang` and `node` parser closures, so start from the closest sibling's.
- Shared test helpers go in `testutils/`.
